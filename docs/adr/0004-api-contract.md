# ADR 0004 — API contract: OpenAPI schema is the single source of truth

- **Status:** Accepted
- **Date:** 2026-08-03
- **Deciders:** Tech lead (Buffy), project owner
- **Technical story:** Sprint 1 API surface design

## Context

Frontend and backend must agree on request/response shapes. Options: hand-maintained
TypeScript DTOs (drift-prone), a shared contracts package (early coupling), or a
schema generated by the backend itself.

## Decision

- The **FastAPI OpenAPI schema** (`/openapi.json`) is the authoritative API
  contract.
- The frontend `lib/api.ts` hand-writes only the few types used today; a
  **typed client is generated from the OpenAPI spec** in Sprint 8
  (e.g. `openapi-typescript` + a thin fetch wrapper) and lives in
  `packages/@evoshield/client`.
- No duplicated DTO definitions across apps beyond that interim hand-written
  subset.

## Consequences

- Contract changes are validated by `tsc` on the generated client — type
  drift fails CI instead of production.
- Frontend ↔ backend stay decoupled: no shared code package required to
  agree on shapes.
- The interim handwritten types in `lib/api.ts` must be replaced when the
  generated client lands (tracked in the Sprint 8 plan).

## Alternatives considered

- **Hand-maintained DTOs everywhere:** rejected — the classic drift source.
- **Shared contracts package now:** rejected — premature coupling; no
  workspace tooling yet (ADR 0003).
